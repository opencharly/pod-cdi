# 2026.321.1527 — refactor(cdi): delegate the strip to layer-cuda, and fix the SONAME typo

## Summary

Three things, all needed before any image can compose this layer. **This is a behaviour change, not
doc-only**: the seed shipped a `run:` step that stripped the driver user-space here, and this PR
removes it — because the strip has one home, `layer-cuda`, which is the layer that installs the package
that drags the driver in (opencharly/layer-cuda#22). What remains here is the contract: the two
assertions and the doctrine.

**1. The removal has exactly one home, and it is not here.** `layer-cuda` installs the CUDA toolkit,
and on the pac path `pacman -S cuda` **depends on `nvidia-utils`** — the toolkit layer is what pulls
the host-coupled driver user-space into an image, so the toolkit layer is what cleans up after
itself. This layer's job is the half that was missing:

- **assert at BUILD time** that no driver library and no `nvidia*` binary survives — a `run:`-adjacent
  `check:` with `context: [deploy]`, where no CDI has injected anything, so a match is unambiguously
  image content;
- **probe at CHECK time** that the container resolved the **injected** driver and that its version
  equals `/proc/driver/nvidia/version` — the only observation that catches a shadowed injection,
  because a shadowed container keeps answering while it computes on the CPU;
- **own the doctrine** (`.agents/skills/cdi/SKILL.md`).

A second copy of the strip here would be a second implementation of one rule, which the rulebook
forbids — and worse, two implementations drift. Nothing consumes this repo yet (it was created and
seeded today; no tag exists and no other repo pins it), so the removal changes no existing consumer:
the strip it deletes has never run anywhere but a build of this manifest.

**2. A typo with a meaning**: the skill said `SONARMEs` where it means `SONAMEs`. The point of the
sentence is that an ICD JSON names a SONAME (`libGLX_nvidia.so.0`), not a version, which is exactly
why the ICDs stay in the image and the injected link satisfies them.

## How tested

**1. Every assertion in this layer DISCRIMINATES across every surface it claims — executed.**

The removal this layer's assertions replace touched **three** surfaces, and the first version of the
check covered only one of them:

| surface | what lived there | covered before |
|---|---|---|
| top-level libraries | `libnvidia-*`, `libcuda*`, `libGLX/EGL/GLES*_nvidia*` | yes |
| driver TREES | `/usr/lib/nvidia`, `/usr/lib64/nvidia`, `/usr/lib/vdpau` (`libvdpau_nvidia.so`) | **no** |
| the xorg driver | `/usr/lib/xorg/modules/drivers/nvidia_drv.so` | **no** |

So an image whose vdpau or xorg driver content survived would have passed an assertion claiming
nothing driver-owned is baked. The check now counts all three, with every path overridable by env
(`CDI_LIB_DIRS`, `CDI_TREE_DIRS`, `CDI_XORG_DRIVER`, space-separated) so the assertion can be pointed at
fixtures and observed failing. Four cases, all executed:

```
A  all three surfaces dirty              -> cdi: driver libraries still baked: 4   exit=1
B  top-level clean, trees+xorg dirty     -> cdi: driver libraries still baked: 3   exit=1
C  only /usr/lib/vdpau dirty             -> cdi: driver libraries still baked: 1   exit=1
D  everything clean                      -> cdi: driver libraries still baked: 0   exit=0
```

Case C is the one the first version could not see. The binary assertion is separate and is proven the
same way (`CDI_BIN_DIRS` over a dirty directory holding a baked `nvidia-smi` ⇒ `still baked: 1`, exit 1;
clean ⇒ `0`, exit 0).
