# 2026.321.1630 — fix(cdi): make the build-time assertions run: steps so the candy can actually be composed

## Summary

Composing this layer failed at build time, which is how it was found:

```
$ charly box build nvidia-cdi          # in opencharly/distro-cachyos, composing layer-cdi
charly: error: command "build": validation errors:
  candy "cdi": must have at least one install file (candy manifest distro: packages, root.yml,
  pixi.toml, ...)
  candy "github.com/opencharly/layer-cdi": must have at least one install file (…)
```

A candy whose plan carries **only `check:` steps is not composable**. The merged revision of this
manifest was exactly that — and the reason its own PR did not catch it is the same reason: nothing
composed the layer yet, so nothing built it. That is a real gap in how I verified it, and it is fixed
here.

Both build-time assertions become `run:` steps — the stricter placement they always wanted:

| step | was | now | why |
|---|---|---|---|
| `cdi-no-baked-driver-libs` | `check:` (`context: [deploy]`) | `run:` (`run_as: root`) | a `run:` cannot be skipped by a check selection; and it executes in the BUILD container, where no CDI has injected anything, so a match is unambiguously image content |
| `cdi-no-baked-driver-binaries` | `check:` (`context: [deploy]`) | `run:` (`run_as: root`) | same |
| `cdi-injected-driver-matches-module` | `check:` (`context: [runtime]`) | **unchanged** | it must run in a GPU-attached container; that is its whole point |

## How tested

**1. The plan is now composable — one install-bearing step at minimum, and two here:**

```
$ python3 -c "import yaml;d=yaml.safe_load(open('charly.yml'));print([(list(s.keys())[0], s.get('id')) for s in d['cdi']['candy']['plan']])"
[('run', 'cdi-no-baked-driver-libs'), ('run', 'cdi-no-baked-driver-binaries'), ('check', 'cdi-injected-driver-matches-module')]
```

**2. The assertions still discriminate after the move** — same fixtures, same commands, now run steps:

```
$ CDI_LIB_DIRS=<dirty lib dir> CDI_TREE_DIRS="<dirty nvidia tree> <dirty vdpau tree>" \
  CDI_XORG_DRIVER=<dirty drv> bash <the cdi-no-baked-driver-libs command>
cdi: driver libraries still baked: 4
exit=1
$ CDI_LIB_DIRS=<clean dir> CDI_TREE_DIRS=<none> CDI_XORG_DRIVER=<none> bash <the same command>
cdi: driver libraries still baked: 0
exit=0
$ bash -n <the same command>        # syntax
(clean)
```

**3. The composition rule, A/B on the same project** — the decisive test, because a `run:` step being
"install content" cannot be assumed from a validator message. The candy was dropped into
`opencharly/distro-cachyos` as a LOCAL candy, composed by `box/nvidia-cdi`, and `charly box validate` run
twice on the same project: once with the merged (check-only) manifest, once with this one.

```
$ cp <check-only candy> candy/cdi-local/charly.yml && charly box validate | grep -c 'must have at least one install file'
1
$ cp <this PR's candy>  candy/cdi-local/charly.yml && charly box validate | grep -c 'must have at least one install file'
0
```

The check-only shape reproduces the exact error; the `run:` shape does not. (The local candy and the box
edit were reverted afterwards; `git status` in that worktree is back to the cutover branch's own diff.)

**4. The consumer build at the minted tag** is the next step in that same cutover PR — producer-first,
because a pin cannot name a tag that does not exist until this merges.
