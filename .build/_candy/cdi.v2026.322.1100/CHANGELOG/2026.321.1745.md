# 2026.321.1745 — fix(cdi): require the CUDA toolkit, so the assertions run AFTER the last driver-installing layer

## Summary

fix(cdi): require the CUDA toolkit, so the assertions run AFTER the last layer that installs a driver

Composing the layer on a real GPU box failed — and the failure was the assertion doing its job on a
half-built image:

```
$ charly box build nvidia-cdi          # opencharly/distro-cachyos, composes layer-nvidia + cdi + cuda
#13 0.131 cdi: driver libraries still baked: 138
#13 ERROR: process … exited with code 1
```

One hundred and thirty-eight driver libraries, in an image that is supposed to carry none. The cause is
ordering, not a missing strip: with no `require:`, the layer sorted BEFORE `layer-cuda` — which is the
layer that installs `cuda`, and on the pac path `pacman -S cuda` **depends on nvidia-utils**, so the
driver user-space appears at that step and its strip runs there. The assertion was reading the image
mid-build and correctly reporting what it saw.

**The fix makes the order a property of the dependency graph rather than of how a box happens to list
its candies:**

```yaml
require:
    - '@github.com/opencharly/layer-cuda:v2026.321.1520'
```

This layer now runs after the toolkit, which is the only placement in which "no driver library is baked"
is a statement about the finished image. A CPU-only image does not compose this layer at all — the CDI
contract is about how a container gets a GPU driver, so an image with no CUDA toolkit has nothing to
assert.

## How tested

**1. The failure that motivates the change, verbatim from the build** — the assertion's own output on the
half-built image, plus the build error that carries it (`cdi: driver libraries still baked: 138`).

**2. The graph now orders the two layers, which is what makes the assertion meaningful:**

```
$ python3 -c "import yaml;d=yaml.safe_load(open('charly.yml'));print(d['cdi']['candy']['require'])"
['@github.com/opencharly/layer-cuda:v2026.321.1520']
```

**3. The assertions themselves still discriminate** — the exact run step, executed against fixtures
(its directories come from `CDI_LIB_DIRS` / `CDI_TREE_DIRS` / `CDI_XORG_DRIVER`, which is why this can be
run outside an image):

```
$ CDI_LIB_DIRS=/tmp/cdi-fix3/dirty/lib \
  CDI_TREE_DIRS="/tmp/cdi-fix3/dirty/nvidia /tmp/cdi-fix3/dirty/vdpau" \
  CDI_XORG_DRIVER=/tmp/cdi-fix3/dirty/xorg/nvidia_drv.so \
  bash <the cdi-no-baked-driver-libs step>
cdi: driver libraries still baked: 4
exit=1

$ CDI_LIB_DIRS=/tmp/cdi-fix3/clean/lib CDI_TREE_DIRS=/tmp/cdi-fix3/clean/none \
  CDI_XORG_DRIVER=/tmp/cdi-fix3/clean/none.so bash <the cdi-no-baked-driver-libs step>
cdi: driver libraries still baked: 0
exit=0
```

The dirty fixture holds one file on each surface the strip touches — a top-level library, one in the
`nvidia` tree, `libvdpau_nvidia.so` in `vdpau`, and the xorg driver — which is why the count is 4.

**4. The ordering fix, proven by building the box** — the same build that produced the 138 failure, with
the reordered candy composed locally:

```
$ cp <this PR's candy> candy/cdi-local/charly.yml   # in opencharly/distro-cachyos
$ charly box build nvidia-cdi
--- Building nvidia-cdi ---
BUILD=0

$ podman run --rm --entrypoint /bin/sh ghcr.io/opencharly/nvidia-cdi:2026.321.1738 \
    -c 'echo "libs=$(ls /usr/lib/libnvidia-*.so* 2>/dev/null | wc -l) bins=$(ls /usr/bin/nvidia* 2>/dev/null | wc -l)"'
libs=0 bins=0
```

Before the requirement the same build stopped at `cdi: driver libraries still baked: 138`; after it the
build completes and the finished image carries none. The local candy and the box edit were reverted, so
that worktree is back to the cutover branch's own diff. The shipping-artifact version of this same build
runs at the tag this merge mints, in the box-cutover PR.

## Change classification

**Breaking change + rollback:** none for a correct consumer — the layer gains a dependency on the CUDA
toolkit, which every GPU image composes anyway; an image that composed `cdi` without a toolkit would now
have to compose the toolkit too, and such an image had nothing for this layer to assert. Rollback is
reverting the field, which restores the unsafe ordering.

Change class: **Layer (candy manifest)** — the require list pasted, the assertion's discriminating runs
re-pasted, and the composing build named as the gate.
