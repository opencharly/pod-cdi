# 2026.322.1325 — feat(pod-cdi): the CDI GPU pod base box

## Summary

A **follow-up pin fix on an existing repo** — not the initial creation. The repo's baseline is
already on `main`; this PR carries exactly four files.

Diff, from `gh pr diff 1`:

```text
diff --git a/.containerignore b/.containerignore    (new)
diff --git a/.dockerignore b/.dockerignore          (new)
diff --git a/.gitignore b/.gitignore                (new)
diff --git a/charly.yml b/charly.yml                (+1/-1)
```

**`charly.yml` — the pin.** `import: cachyos:` moves from `distro-cachyos:v2026.322.1210`
to `v2026.322.1045`. The old value was not a repository tag at all: I copied an image CalVer
out of `.build/nvidia/` and wrote it as if it were one, and the build rejected it:

```text
charly: error: import cachyos ("@github.com/opencharly/distro-cachyos:v2026.322.1210"):
  downloading remote ref …: InvokeProvider
```

The corrected tag is proven, not asserted:

```console
$ git ls-remote --tags https://github.com/opencharly/distro-cachyos.git | grep 'v2026.322.1045'
98f97d43fdd894ce3ee3779cc7efe008a896a450	refs/tags/v2026.322.1045
```

**The three ignore files are GENERATED** — `source: defaults.context_ignore` in `charly.yml`,
emitted by the generator, not hand-written. Their content is identical in both dot-files and
matches the configured context-ignore list:

```console
$ head -5 .containerignore
# .containerignore (generated -- do not edit; source: defaults.context_ignore)
.git
bin
charly
*.md
```

`.gitignore` carries the build-artifact rule (`.build/`, `.check/`) so a `charly box build`
run inside this repo cannot sweep its cache into a commit — which is what happened on the
previous head, where 447 `.build` files reached the index.

## How tested

The box builds with the corrected pin:

```console
$ charly -C . box build pod-cdi
rc=0

$ podman run --rm --entrypoint sh localhost/pod-cdi:2026.322.1240 -c \
    'command -v nvidia-ctk; ls /usr/lib64/libcuda.so*'
nvidia-ctk: ABSENT
libcuda:
```

`layer-cdi`'s own plan steps fail the build when a host-coupled driver library or nvidia
binary is baked; the build passed, so the pod contract holds.

**Not proven:** there is no `.build/` deletion in this diff, and I state that plainly rather
than claiming one. The previous commit message said "untrack `.build`", but the baseline on
`main` never carried those files, so that message overstates what the diff does — reconciled
here rather than left to mislead.
