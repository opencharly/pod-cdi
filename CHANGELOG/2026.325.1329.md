# 2026.325.1329 — fix(pins): advance the arch import so the CDI base stops emitting the retired carrier COPY

## Summary

Advances the `arch` import pin so the generator stops emitting the retired carrier step, and every
image built on this base stops failing a cold build (opencharly/pod-cdi#9).

**The defect, measured.** With charly `2026.325.1102` (the release carrying the owned-skill chain
sdk#607 / plugin-box#92 / plugin-build#63), the `kde-vnc` box — `base: podcdi.pod-cdi` — built
through this base emitted:

```
#9  [arch-skills 1/1] COPY .build/_candy/arch-skills/ /
#10 [stage-1 6/7] COPY --from=arch-skills --chmod=0755 --chown=1000:1000 .agents/skills /home/user/.agents/skills
#10 ERROR: failed to calculate checksum of ref …: "/.agents/skills": not found
```

That is the pre-#76 shape. The carrier fix reaches a project **only through its `arch` import pin**:
a consumer's own `arch:` import cannot change the base image it inherits from `podcdi.pod-cdi`, so
this repo is the one place the fix can hold for the whole GPU family.

**The change.** One line — `arch` → `v2026.325.1112`, distro-arch's current release — plus the
comment recording WHY the pin must track it. `charly box validate`: OK — 131 candies, 11 boxes,
6 distros, 7 builders; 0 warnings, 0 errors.
