# 2026.322.1717 — fix(pod-cdi)!: break the import cycle so a consumer can compose and build this box

## Summary

The box declares its **own base, vocabulary and builder map**, so that a consumer can compose and build it. One file changes.

Diff, from `gh pr view 4 --json additions,deletions,changedFiles`:

```text
+34 -3 files=1
```

**Three behavioural changes, all in `charly.yml`, all forced by the same rule.**

**1 — the base is now the upstream image by digest, not an import.**
This repo imported `distro-cachyos` for its `cachyos` base — and `distro-cachyos` is the repo that *consumes* this box, because every GPU pod there now bases on `podcdi.pod-cdi`. Importing it back is a **cycle**.

To be exact about what the quoted failure is and is not: it is **not** produced by this PR. It is the pre-change behaviour — the reason this file changes — reproduced by building the consumer against the published tag `v2026.322.1325`, which still carries the import:

```console
$ charly -C . box build comfyui          # distro-cachyos, base: podcdi.pod-cdi @ v2026.322.1325
generating Containerfile for podcdi.pod-cdi: candy layer-direnv:
  resolved 1 package(s) [direnv] but box pod-cdi has no distro definition to install into
```

On this branch the same command succeeds, at `0 warnings` — that is the "How tested" block below, run on `f2ab311`. The PR touches only `charly.yml` in **this** repo; it changes no consumer and no layer.

`base:` is now the same coordinate `distro-cachyos`'s own `box/cachyos` pins —
`docker.io/cachyos/cachyos-v3@sha256:f50fa2954…ba94184b` — and the `cachyos` import is gone. Nothing imports this repo back; this repo imports only `distro-arch`, for the builder.

**2 — the box declares its own distro vocabulary.** Basing on a raw OCI image inherits none, so the box gained `distro: [cachyos, arch]`. Without it `layer-direnv` (pulled in by `layer-agent-forwarding`) has nothing to install into — the error above.

**3 — the box declares its own `build:` and `builder:` map.** Both are stated outright in `distro-cachyos`'s `box/cachyos`:

> *"CachyOS is Arch-derived and has no builder of its own; route all four formats to arch.arch-builder … **Builder maps do NOT cross a namespace boundary, so a consumer that builds declares its own builder map.**"*

Without them a consumer fails with `box "comfyui": candy "pod-comfyui" needs builder "pixi" but no builder.pixi configured`, and before that with `image pod-cdi: build: field required`.

## Change classification

A base-box repo gains a self-contained base, vocabulary and builder map, and drops its dependency on the repo that consumes it.

**Breaking change + rollback:** consumers currently composing `podcdi.pod-cdi` cannot build while this repo imports `distro-cachyos`, because that is the cycle. Rollback returns the repo to a base it cannot be composed from — that is the state this PR fixes, not a safe fallback, so rollback means reverting the consumer pins first.
